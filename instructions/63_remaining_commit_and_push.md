# 63: 残っている未コミット変更のコミット・push(AI出所表示・タグ付きClient/Device等)

## 背景

- 直前(コミット17fd3a3)で`.gitignore`整理とdemoスクリプト14個の追跡解除のみをコミット・pushした
- その際の`git status`で、それとは別に以下が未コミットのまま残っていることが判明した:
  - `plugins/tagged-targets/`ディレクトリ全体(未追跡、59番で実装したタグ付きClient/Device機能一式)
  - `plugins/network-investigation/ai-source.ts`、`plugins/network-investigation/view/AiSource.tsx`(未追跡、56番のAI出所表示機能)
  - `plugins/global-overview/central-client.ts`・`mist-client.ts`、`plugins/network-investigation/`配下の複数ファイル、`server/index.ts`、`src/i18n/en.json`・`ja.json`、`src/main.tsx`(変更済みだが未ステージ)
  - `instructions/56〜62番`の指示ファイル・findingsファイル一式(未追跡)
- 55番の初回公開時と同様に、push前のセキュリティ監査を必ず行う

## タスク

### Task 1: 変更内容の棚卸し

1. `git status`で現在の変更・未追跡ファイルの全体像を再確認する
2. 各ファイルがどの番号(56・57・58・59番など)の作業に対応するか、簡単に対応付けを確認する(コミットメッセージの粒度を決めるため)

### Task 2: セキュリティ監査(必須、push前に完了させること)

1. `git diff`(未ステージ分)と、新規追加予定の全ファイルの内容を対象に、以下が含まれていないことを確認する:
   - 実際のSSID名・サイト名・デバイスシリアル・MACアドレス等の実データ
   - APIトークン・パスワード・RADIUS共有シークレット等の秘匿情報
   - 顧客名・組織名等、公開を意図していない固有名詞
2. 特にタグ付きClient/Device機能(59番)はMAC/IPアドレス等の実データを扱う機能なので、テストデータ・サンプルコードに実際の値がハードコードされていないか重点的に確認する
3. `instructions/`配下のfindingsファイル群(56〜62番)にも、調査中に扱った実データ(サイト名等)が伏字化されずに残っていないか確認する
4. 問題があれば伏字化・除外してから次に進む

### Task 3: コミット

1. 論理的にまとまった単位でコミットを分ける(目安: AI出所表示関連、タグ付きClient/Device関連、その他の変更、instructions/ドキュメント、のように分ける。1つにまとめても良いが後から追いやすい粒度を優先する)
2. コミットメッセージは何を追加・変更したかが分かる内容にする

### Task 4: push

1. `git push origin main`でGitHubリポジトリに反映する
2. push後、GitHub上でファイル一覧・差分を確認し、意図しないファイル(機密情報や個人環境固有のパス等)が含まれていないことを再確認する

## 制約

- pushする前に必ずTask 2のセキュリティ監査を完了させること。監査で疑わしい内容が見つかった場合は、pushを止めて内容を報告し指示を仰ぐこと
- 本番のSSID・WLAN設定の変更は行わない(このタスクの範囲外)

## 完了報告

verified-report形式で報告すること。特に:

- コミットした単位ごとのファイル一覧とコミットメッセージ
- セキュリティ監査の実施内容と結果
- pushが成功したことの確認(GitHub上での確認結果含む)
- コミット対象から意図的に外したもの(あれば)とその理由
