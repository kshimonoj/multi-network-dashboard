# 39: デモ動画作成(ネットワーク調査: Sonnet vs Local(gemma4:12b)の実行時間比較、「続けて調べる」含む)

## 目的

34〜38番と同じ録画環境(Playwright + ffmpeg)を使い、**同じ調査フロー(初回クエリ+「続けて調べる」)をSonnetとLocal(gemma4:12b)それぞれで実行し、26番で実装済みの所要時間表示(タイムライン)を使って速度差を見せる**デモ動画を作成する。字幕は36番以降と同じ「です・ます調」で統一する。

## 前提

- Localモデルは過去の実測で1回の実行に数十秒〜4分近くかかることが分かっている(25番参照)。録画時間が非常に長くなるため、**Local実行中の待機区間は積極的に早送り編集(36番で使ったtrim+setpts、3倍速程度)を適用すること**。Sonnet側は比較的短いはずなので、早送りの要否は実際の録画を見て判断してよい
- 同じ質問文を両モデルで使うことで、速度差が公平に伝わるようにする。質問は既存のInsight Agentが扱いやすい内容(例:「Homeサイトの状態を教えて」)+「続けて調べる」で1ターン追加、という2ターン構成をSonnet・Local双方で行う
- SonnetとLocalは別々のセッション(スレッド)として実行してよい(同一スレッドで両方のモデルを跨ぐ必要はない)

## タスク

### Task 1: Sonnetでの実行

1. ネットワーク調査タブで、モデル選択をSonnetにし、質問(例:「Homeサイトの状態を教えて」)を実行する
2. 回答後、「続けて調べる」のワンクリック操作(36番で特定済みの`.ni-chip`)で追加の関連質問を実行する
3. 2ターン完了後、実行タイムライン上に所要時間(秒)が表示されている状態を撮影する

### Task 2: Localでの実行(同一質問)

1. モデル選択をLocal(gemma4:12b)に切り替え、Task 1と同じ質問文で新規に実行する(新しいセッションでよい)
2. 回答後、同様に「続けて調べる」で追加の関連質問(Task 1と同一内容の追い質問が望ましいが、モデルの提示するチップ文言に従ってよい)を実行する
3. 待機時間が長い区間は早送り編集の対象としてマークしておく(後段のTask 3で使う)

### Task 3: 比較が伝わる画面の撮影

1. 両方の実行が完了した後、実行タイムライン(またはセッション一覧)で、Sonnet実行とLocal実行それぞれの所要時間が並んで見える状態を撮影する(スクロールして両方が画面に収まるようにする、または2回に分けて両方を映す)
2. 実際の所要時間の数値(秒)がはっきり読み取れるようにする

### Task 4: 早送り編集

1. Local実行中の待機区間(SSEログがゆっくり流れるだけの時間)を特定し、3倍速程度で早送りする(36番のffmpeg手法を踏襲)
2. Sonnet側も明らかに間延びする区間があれば同様に早送りしてよい
3. 36番で不要と判断された「速度バッジ」の表示は、今回も付けないこと(37番の対応を踏まえる)

### Task 5: 字幕の焼き込み(です・ます調)

各場面に合わせて日本語字幕を焼き込む。例:

- 「① Sonnetでネットワーク調査を実行します」
- 「② 続けて調べるをクリックし、深掘りします」
- 「③ Sonnetでの所要時間が記録されます」
- 「④ 同じ質問をLocal(gemma4:12b)で実行します」
- 「⑤ Localでも続けて調べるを行います」
- 「⑥ SonnetとLocalの所要時間を見比べます」

実際の所要時間の数値が分かっている場合は、字幕に具体的な秒数を含めてもよい(例:「SonnetはX秒、LocalはY秒でした」)。

### Task 6: 出力・確認

1. `.webm`を`.mp4`に変換する
2. `demo/`ディレクトリに、既存の動画と区別できるファイル名で保存する(例: `demo_03_model_comparison.mp4`)。既存ファイルは上書きしない
3. 動画の長さ・ファイルサイズ・保存先パスを確認する
4. 既存の他の動画ファイルに影響が無いことを確認する

## 完了報告

verified-report形式で報告すること。特に:

- 使用した質問文・「続けて調べる」で実際に選んだ追加質問
- Sonnet・Localそれぞれの実測所要時間
- 早送り編集の適用区間・倍率
- 動画の長さ・ファイルサイズ・保存先パス
- 既存ファイルへの影響が無いことの確認

git操作は行わないこと。
