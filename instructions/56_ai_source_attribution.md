# 56: ネットワーク調査結果でのAI出所表示(Marvis AI/Central AIOps由来 vs Insight Agent自身の分析)

## 背景

- ネットワーク調査(Insight Agent)は、Claude/Local LLMがMCP(central-mcp/mist-cloud)経由でCentral/Mistを調査する機能
- Mist側には`get_mist_insights(insight_type=marvis_actions)`という、Mistのネイティブ機能(Marvis AI)が生成した所見を取得するツールが既に存在する(49番のベストプラクティス調査で確認済み)。同様にCentral側にも同種のAI/健全性スコア系の情報を返すツールがあれば対象に含める
- 現状、調査結果にはどのMCPツールを呼び出したかの記録(durationMsのタイムライン表示)はあるが、「その情報がCentral/Mistのネイティブ機能(Marvis AI等)由来なのか、Insight Agent自身(Claude/Local LLM)の分析なのか」を利用者が見分けられる表示にはなっていない
- 53番で実装した「AI所見」バッジ+注記の表示パターン(スナップショットの値のみを根拠にした参考情報である旨を明示する)と一貫性を持たせる

## 目的

ネットワーク調査の回答画面で、以下が利用者に伝わるようにする:
- どの部分がCentral/Mistのネイティブ機能(Marvis AI / 同等のCentral機能があれば)から得られた情報か
- どの部分がInsight Agent自身(Claude/Local LLM)の分析・推論か

## タスク

### Task 1: ツール呼び出しの出所分類

1. 既存のMCPツール呼び出しログ(durationMsタイムラインの記録箇所)を調査し、呼び出されたツール名を分類するロジックを追加する
   - 「Central/Mistネイティブ機能由来」に分類するツール: `get_mist_insights`(Marvis Actions等)、Central側で同種の機能があれば同様に分類(要調査。無ければMist側のみの対応とする)
   - それ以外(central_get_devices等の生REST値取得)は「生データ取得」として区別する(ネイティブAIの所見ではない)
2. 分類結果をツール呼び出しの記録に併せて保存する(既存のdurationMsログの構造に出所フィールドを追加する形が自然かどうかを調査し、既存構造に合わせて実装する)

### Task 2: 調査結果画面での表示

1. 調査結果(回答本文)の中で、Marvis AI等のネイティブ機能由来の情報を参照・引用している箇所が分かるよう、該当ツール呼び出しにバッジ(例:「Marvis AI由来」)を付ける
2. 53番のAI所見バッジと同様に、「これはCentral/Mistのネイティブ機能が生成した所見であり、Insight Agent自身の分析ではありません」という趣旨の注記を付ける
3. 既存のタイムライン表示(durationMs等)に、出所(ネイティブAI由来/生データ取得/Insight Agent自身の分析)が一目で分かる表示を追加する
4. i18n対応(ja.json/en.json)を行う

### Task 3: 動作確認

1. Mistサイトで実際にMarvis Actionsが関与する調査を行い、バッジ・注記が意図通り表示されることを確認する
2. Central側でネイティブAI機能に相当するツールが無い場合、その旨をfindingsに明記する(無理に対応する必要はない)
3. 通常の生データ取得のみの調査(Marvis Actions等を呼ばない調査)では、従来通りの表示のままであることを確認する
4. 日英切替・ダークモードでの表示崩れが無いことを確認する

## 制約

- 本番のSSID・WLAN設定の変更は一切行わない
- git操作は行わない(コミット等は別途指示があるまで実施しない)
- 既存タブのデザイン言語・53番のAI所見バッジのパターンに合わせる

- Central側にネイティブAI機能相当のツールがあったかどうかの調査結果
- i18n・表示崩れの確認結果
