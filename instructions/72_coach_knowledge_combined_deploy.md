# 72: 70・71番の統合本番反映(rebuild + 8092動作確認)

## 背景

- 70番(Coach: 速度改善・履歴閲覧・エスカレーションループ修正・ヒント前置き修正)と71番(Knowledge: 承認済みとの重複検出)は、どちらも実装・dev環境での検証まで完了している
- 両方とも「並行作業が完了してから本番反映」という指示だったため、まだ本番(8092)には反映されていない
- 今回、両方を一緒に本番反映し、統合された状態で動作確認する

## タスク

### Task 1: 本番反映

1. `git status`で70・71番それぞれの変更が両方ともワーキングツリーに揃っていることを確認する
2. `docker compose up -d --build`で本番コンテナ(8092)へ反映する
3. コンテナが正常に起動していること(`docker compose logs`にエラーが無いこと)を確認する

### Task 2: 70番(Coach)の動作確認(本番8092)

1. 速度改善: 壁打ちの1ターン目(hintLevel0)でライブMCPを引かないことを確認し、体感速度が改善していることを確認する。「今どうなってる?」等、明示的にライブ確認を求めた場合は従来通りライブを引くことも確認する
2. 履歴閲覧: 新設された「履歴」モードで、過去の壁打ちセッション一覧(要約)が表示され、行を開くと全文が展開されることを確認する
3. エスカレーションループ修正: 「もう答えを教えて」を押した際、回答末尾に疑問形の追加質問が付かず、開示で会話が一区切りつくことを確認する。クイズの「答えを見る」でも同様に確認する
4. ヒント前置き修正: 「ヒントをもう1つ」をクリックした際、不自然な前置き(「発言が無い」等の指摘)なしに、素直に次のヒントが出ることを確認する(70番の申し送り通り、元々低頻度の症状のため再現しなくても問題ない)
5. 70番で未確認だった「履歴画面の狭い画面(900px未満)でのレイアウト」を、本番でブラウザ幅を実際に狭めて確認する
6. 日英切替・ダーク/ライトモードでの表示崩れが無いことを確認する(履歴モードを含む)

### Task 3: 71番(Knowledge)の動作確認(本番8092)

1. ナレッジタブの未承認リストに、「承認済みとの重複を検出」機能が表示され、実行できることを確認する
2. 実際に本番の未承認リスト(52件前後、71番の検証時点の件数)に対して重複検出を実行し、rogue AP関連の重複が正しく検出・統合(merge)されることを確認する
3. 統合後、該当の承認済みエントリの出典が増えている(本文は変わらない)ことを確認する
4. 過剰検出が起きていないか(新規性のある知見が誤って握りつぶされていないか)を確認する
5. 一括検出の所要時間(71番の検証では50件で約8分)を踏まえ、実行中の画面表示に問題が無いか確認する

### Task 4: 相互影響の確認

1. Coach(70番)がKnowledgeの承認済みエントリを参照する際、71番の変更(重複統合等)が悪影響を与えていないか確認する(Coachの根拠リンクが正しく機能するか)
2. 既存の他機能(ベストプラクティス診断、Tagged Targets、レポート等)に副作用が出ていないことを一通り確認する

## 制約

- git操作は行わない(コミット等は別途指示があるまで実施しない)
