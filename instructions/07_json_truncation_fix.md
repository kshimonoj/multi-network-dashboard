# 07: 「サイト指定なし」クエリでのJSONパースエラー修正(multi-network-dashboard)

## 症状

ネットワーク調査ページで「サイト指定なし(両方に問い合わせ)」を選んでクエリを実行すると失敗する。エラー表示:

```
Unterminated string in JSON at position 136653 (line 3689 column 19)
```

呼び出したツールは0件と表示され、実行結果自体が得られていない。サイト指定ありのクエリ(Central/Mistどちらか一方のみに絞り込まれるもの)では発生していない模様。

## 想定原因(調査で確認すること)

サイト指定なしの場合、Central・Mist両方のMCPツールを呼び出すためclaude CLI subprocessの出力量がサイト指定時より大幅に増える。エラーメッセージの位置(3689行目)から、かなり大きな出力の途中でJSONが途切れていることが分かる。以下を疑って調査する:

1. claude CLIのsubprocess出力を読み取っている箇所(`insight-agent.ts`または`mcp.ts`)で、出力をどう読み取り・分割・パースしているか確認する(`--output-format stream-json`等でNDJSON形式なら1行ごとにJSON.parseしているはずだが、stdoutのdataイベントが1行の途中で分割された場合に、前のチャンクの残りと結合せずにパースしてしまっていないか)
2. Node.jsの`child_process`(`spawn`/`exec`)で`maxBuffer`のようなサイズ上限が設定されていて、出力の途中で打ち切られていないか確認する
3. サイト指定ありの小さい出力と、サイト指定なしの大きい出力で、実際のバイト数・行数を比較し、閾値が存在するかを特定する

## タスク

### Task 1: 再現と原因特定

1. 実際に「サイト指定なし」でクエリを実行し、claude CLI subprocessの生出力(stdout)をログに落として確認する(可能であれば一時的にデバッグログを追加してよい)
2. エラーが発生している具体的な処理箇所(何行目のコードで、どういう入力に対してJSON.parseが失敗しているか)を特定する
3. 上記「想定原因」のうちどれが実際の原因かを確認し、`instructions/07_findings.md`に記録する

### Task 2: 修正

原因に応じて適切な修正を行う。可能性が高い対応の例:

- 出力読み取りロジックが行単位のバッファリングを正しく行っていない場合: stdoutのdataイベントをバッファに蓄積し、改行文字で区切られた完全な行だけをパースする(改行が来ていない末尾は次のチャンクと結合してから再度チェックする)実装に修正する
- `maxBuffer`等のサイズ上限が原因の場合: 上限を十分に大きい値に引き上げる、またはストリーミング処理に切り替えて上限自体を撤廃する

### Task 3: 検証

1. 修正後、実際に「サイト指定なし」で複数回クエリを実行し、正常に完了することを確認する(横断的な調査、複数ターンの「続けて調べる」も含めて確認する)
2. 意図的に大きな応答が返るようなクエリ(多くのサイト・多くのツール呼び出しを要するもの)でも失敗しないことを確認する
3. 従来通りサイト指定ありのクエリが引き続き問題なく動作することを確認する(退行がないこと)
4. `docker compose up -d --build`で反映し、`/health`と実画面を確認する
