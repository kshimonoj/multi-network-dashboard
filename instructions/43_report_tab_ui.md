# 43: レポートタブUI(カレンダーピッカー・KPI・グラフ・出来事/問題一覧)

## 前提・確定事項

- 41〜42番で日次レポートの生成・保存基盤は完成済み(`GET /api/reports/daily`一覧、`GET /api/reports/daily/:date`詳細がそのまま使える)。今回はその**表示画面**を作る
- 週次/月次の集計ロジックはまだ実装していない(44番で対応予定)。今回のタブでは期間タブ(日次/週次/月次)自体は用意するが、週次/月次を選んだ場合は「準備中」であることが分かる表示にしておいてよい(空データでエラーにならないようにする)
- トラフィック量のKPIは表示しない(取得不可のため)
- Central「平均健全性」とMist「平均SLE」は同じ0〜100スケールの1本の折れ線グラフに2系列として表示し、サイト別・Wireless/Wired等の内訳は表示しない(既存のGlobal Overviewサイト詳細ページへのリンクで代替する)
- 「起きたこと」「検出された問題」には対象機器・発生日時を表示し、クリックで詳細(ネットワーク調査への連携、または関連する既存画面)に遷移できるようにする
- 期間の選択はカレンダー的なUI(日付/週/月を選べるカレンダー表示)にする。横スクロールのピル一覧ではない

## タスク

### Task 1: 新しい「レポート」タブの追加

1. 既存のタブシェルに「レポート」タブを追加する(既存の5タブと並ぶ形)
2. 期間タブ(日次/週次/月次)を設置する

### Task 2: カレンダー的な期間ピッカー

1. 日次選択時: 月表示のカレンダーグリッドから日付を選べるUIを実装する。レポートが存在する日(生成済み)は選択可能、存在しない日は薄く表示するかグレーアウトする
2. 週次選択時: 週単位で選べるカレンダー的なUI(月表示から週をハイライトして選ぶ、または週の開始日のリストから選ぶ、実装しやすい形でよい)。ただし週次データが無い場合は「準備中」の表示にする
3. 月次選択時: 月を選べるUI(年月のリスト、または簡易な年月ピッカー)。同様にデータが無い場合は「準備中」の表示にする
4. 選択した日付に対応するレポートを`GET /api/reports/daily/:date`から取得して表示する

### Task 3: KPI・グラフの実装

1. KPIカード: 総イベント数、重大アラート数、接続端末数、新規の問題数(トラフィック量は含めない)
2. 健全性/SLEトレンドグラフ: New Central「平均健全性」とMist「平均SLE」を1つのグラフに2系列で表示する(グラフの下に「サイト別・詳細な内訳は各サイト詳細ページで確認できます」という注記+実際のリンクを設置する。リンク先は既存のGlobal Overviewのサイト詳細ページ)
3. 利用量トレンドグラフ: 接続端末数の推移
4. 日次レポート単体では「推移」と呼べるほどの点数が無い(1日分の値のみ)可能性があるため、直近N日分(例: 直近7日)の日次レポートを並べて簡易的なトレンドとして見せる形でもよい(週次/月次の本実装が44番で入るまでの代替として)

### Task 4: 「起きたこと」「検出された問題」の表示

1. 「この期間に起きたこと」: 発生日時・対象機器・内容を表示するリスト。各項目をクリックすると、その内容を踏まえたクエリでネットワーク調査タブに遷移する(既存のpendingInvestigationQuery共有stateパターンを流用する)
2. 「検出された問題」: 表形式で表示する。列は少なくとも「問題」「対象機器」「初回発生」「プラットフォーム」「重要度」「再発性」「次のアクション」を含める(根本原因・影響範囲は列を追加するか、行クリックで展開する詳細に含めるか実装しやすい方でよい)。表の幅が画面に収まらない場合は横スクロール可能にする
3. 表の行もクリックでネットワーク調査タブへ連携できるようにする

### Task 5: 動作確認

1. 実際に生成済みの日次レポートをカレンダーから選び、KPI・グラフ・出来事・問題一覧が正しく表示されることを確認する
2. 週次/月次を選んだ場合に「準備中」等の表示になり、エラーにならないことを確認する
3. 「起きたこと」「検出された問題」のクリックでネットワーク調査タブに正しく遷移することを確認する
4. サイト詳細ページへのリンクが正しく機能することを確認する
5. ダークモード両テーマ・日英切替(i18n辞書に新規文言を追加すること)の表示を確認する
6. `docker compose up -d --build`で反映し、実画面を確認する
