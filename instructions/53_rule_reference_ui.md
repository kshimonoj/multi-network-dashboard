# 53: ルール説明の可視化(結果一覧の展開表示 + ルールリファレンスページ)

## 背景(49〜52番からの引き継ぎ)

- 49番でルール(29 ID、機械判定25+LLM所見4)を設計、51番で実行エンジン・API、52番でタブUI(サイト選択→診断実行→結果一覧表示)まで実装済み
- 現状の結果一覧は、各ルールについて判定値(pass/fail/warn/unknown)とID(SEC-12、RF-15等)は表示されるが、そのIDが何を診断しているルールなのか・なぜベストプラクティスとされているのかが画面から分からない、という課題が見つかった
- 各ルールには`bestPractice.rules.<ID>.title`/`.desc`のi18nキーがすでに用意されており、`references[]`(根拠URL)もルール定義に含まれている

## 今回の対応方針(確定事項)

1. **診断結果一覧の各行を展開できるようにする**: クリック(またはアイコン)でtitle・desc・なぜベストプラクティスなのか・references[]へのリンクをその場で表示する
2. **独立した「ルール一覧/リファレンス」ページを新設する**: 診断を実行していなくても、29ルール全部について「何を診断しているか」「なぜベストプラクティスか」「参考資料」を常時閲覧できる一覧ページを作る
3. 結果一覧の各行から、対応するリファレンスページの該当ルールへリンク/展開できるようにする(1と2を繋ぐ)

## タスク

### Task 1: 結果一覧の展開表示

1. 52番で実装した結果一覧の各行(ルールごとの判定表示)にクリック可能な展開UIを追加する
2. 展開すると以下を表示する: ルールのtitle(既存i18nキー)、desc(既存i18nキー)、category、priority、method、references[](リンクとして開けるように)
3. requiresLegalReview対象のルール(SEC-10/11)は、展開時に「なぜ法務確認が必要とされているか」が分かる説明も含める
4. AI所見系(SEC-12/13, RF-15/16)は、展開時に「これはルールベースの自動判定ではなく、設定内容をAIが確認して書いた所見である」ことが分かる説明を含める

### Task 2: ルールリファレンスページの新設

1. 診断結果とは独立した、29ルール全部を常時閲覧できる一覧ページ(タブまたは既存「ベストプラクティス」タブ内のサブビュー、どちらが既存の構成に馴染むか判断して選んでよい)を作る
2. 各ルールについてtitle・desc・category・priority・method・references[]を表示する
3. カテゴリ(セキュリティ/RF)ごとにグルーピングし、機械判定ルールとAI所見ルールが見分けられるようにする(52番のバッジ表現と一貫性を持たせる)
4. 診断を実行していない状態でもこのページ単体で閲覧できること(サイト選択・診断実行は不要)

### Task 3: i18n対応

1. 新規に追加する文言(展開表示のラベル、リファレンスページのタイトル等)をja.json/en.json両方に追加する
2. 既存のtitle/descキーは流用し、重複定義を作らない

### Task 4: 動作確認

1. 結果一覧から各行を展開してtitle/desc/referencesが正しく表示されることを確認する
2. requiresLegalReview対象・AI所見対象の説明文が意図通り表示されることを確認する
3. リファレンスページが診断実行なしで単独で閲覧できることを確認する
4. 日英切替・ダークモードでの表示崩れが無いことを確認する
5. 既存の他タブ・既存の結果一覧表示への影響が無いことを確認する

## 制約

- 本番のSSID・WLAN設定の変更は一切行わない
- git操作は行わない
- 既存タブのデザイン言語(色使い・レイアウト・コンポーネント)に合わせる

- i18nキーの追加内容と重複が無いことの確認
- 既存表示への影響有無
