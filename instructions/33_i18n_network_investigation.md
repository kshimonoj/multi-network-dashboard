# 33: ネットワーク調査タブの辞書化 + レイアウト崩れ懸念(L-5/L-9/L-10/L-11)対応

## 前提

29〜32番で確立したパターン(`src/i18n/ja.json`/`en.json`への名前空間追加 + `t()`経由の表示)を踏襲する。ネットワーク調査タブは28番findingsで最大規模(383件)だったが、そのうち「LLM prompt」区分の102件はすでに29番でInsight Agentのsystem prompt日英化として対応済みのため、**実質的な残り作業は静的UI文言220件+srv→UI 61件**になる。着手前に、28番findingsの記載が現在のコード上で本当にこの規模かをgrep等で再確認すること(31・32番と同様)。

規模が大きいため、1回で終わらない場合は`instructions/33_findings.md`に途中経過を残しながら進めてよい。

## タスク

### Task 1: 対象範囲の再確認

1. `plugins/network-investigation/view/`配下(NetworkInvestigation.tsx, Turn.tsx, Timeline.tsx, HistoryThread.tsx, ScheduleEditor.tsx, ToolCallRow.tsx, SseLog.tsx, SessionShare.tsx, ShareActions.tsx等)の日本語文言を実際にgrepし、28番findingsの記載と照合する
2. LLM prompt区分(102件)が29番で既に対応済みであることを確認し、二重対応しないようにする

### Task 2: ネットワーク調査タブの辞書化(静的UI文言)

1. `networkInvestigation.*`名前空間を`ja.json`/`en.json`に追加し、対象コンポーネントを`t()`経由の表示に置き換える
2. サイト選択・モデル選択(Sonnet/Opus/Local)・実行ボタン・「このスレッドの続きとして実行する」チェックボックス・タイムライン・履歴詳細・ツール呼び出しログ・スケジュール設定UI等を対象に含める

### Task 3: レイアウト崩れ懸念(L-5/L-9/L-10/L-11)への対応

1. **L-5(ScheduleEditor.tsxの曜日ボタン7個)**: 英語表示では「Mon/Tue/Wed...」のような3文字表記になり、日本語の「月/火/水...」1文字と比べて幅が必要になる。ボタン幅を可変にするか、英語表示時のみ省略形(M/T/W/T/F/S/S等、曜日が一意に判別できる形)を使うか検討し、レイアウトが崩れないようにする
2. **L-9(shareText.tsの共有テキストの桁揃え)**: 全角スペースで手動整列している箇所は、英語表示では全角スペースの概念自体が不自然になる。英語版は半角スペースまたは適切な区切り文字で整列し直す
3. **L-10(toLocaleString("ja-JP")のハードコード10箇所)**: 現在の言語設定に応じて`toLocaleString("ja-JP")`/`toLocaleString("en-US")`(または`Intl.DateTimeFormat`)を切り替えるよう修正する。既存の日本語表示時の見た目(フォーマット)は変えない
4. **L-11(相対時刻「n秒前」の4実装)**: 31番でWebhookログ側に作った`time.relative.*`辞書(英語の単数/複数対応含む)を、ネットワーク調査タブ側の4箇所の実装からも共通で使えるように統合する(重複実装を1箇所に集約できるならその方が望ましいが、無理に大きなリファクタリングをする必要はない。辞書を共有すること自体を優先する)

### Task 4: srv→UI文言(61件)の対応方針

1. 29〜32番と同じ判断基準(バックグラウンドで生成され特定閲覧者の言語コンテキストを持たない文言は現状維持でよい)に沿って判断する
2. ネットワーク調査タブ特有の事情(例: スケジュール実行・自動調査由来の文言等)があれば、その旨を記録した上で対応要否を判断する

### Task 5: 動作確認

1. ネットワーク調査タブで日英切替を行い、全要素が正しく切り替わることを確認する
2. L-5〜L-11それぞれの対応箇所を英語表示で確認し、崩れていないことを確認する
3. 日本語表示時の見た目(特にL-10の日時フォーマット)に変化が無いことを確認する
4. 既存の辞書化済み4タブへの影響が無いことを確認する
5. ダークモード両テーマでの表示を確認する
6. `docker compose up -d --build`で反映し、実画面を確認する
