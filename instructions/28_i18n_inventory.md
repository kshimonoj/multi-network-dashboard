# 28: 日英切替(i18n)対応の文言棚卸し調査(実装は行わない)

## 目的

日本語⇔英語の表示切替を本格的に実装する前段として、アプリ全体(ネットワーク調査/Global Overview/Webhookログ/Streaming(Central)の4タブ + 共有コンポーネント)に含まれる日本語文言を棚卸しし、後続の実装指示ファイルの設計材料にする。**このタスクでは実装・コード変更は一切行わない。**

## 前提・方針

- 今の日本語UIの見た目・レイアウトは基本的に崩さない方針。英語化した際に明らかにレイアウトが崩れそうな箇所があれば、その旨も記録しておく(対応要否の判断は後続タスクで行う)
- i18n基盤は既存のダークモード切替と同じパターン(軽量な自前Context + JSON辞書)を採用予定。追加ライブラリは導入しない前提

## タスク

### Task 1: 静的ラベルの棚卸し

1. 4タブ+共有コンポーネント(タブシェル、ヘッダー、共有ボタン群、設定UI等)に含まれる、ソースコード上に直接書かれている日本語の文言(ボタンラベル、見出し、プレースホルダー、ツールチップ、エラーメッセージ等)を全て洗い出す
2. ファイルごとに「文言の一覧」を作成し、以下の情報を付与する:
   - 出現ファイル・おおよその行番号
   - 文言そのもの
   - 種別(ボタン/見出し/ラベル/エラーメッセージ/ツールチップ等)
   - 英語化した場合に文字数が大きく増えてレイアウトが崩れそうかどうかの所見(明らかなものだけでよい、厳密な判定は不要)

### Task 2: 動的生成文の棚卸し(特に重要)

単純な辞書引きでは対応できない、**実行時に文章を組み立てている箇所**を特定する。少なくとも以下は含めること:

1. 「調査する」ボタンが自動生成する調査クエリ文(`buildInvestigationQuery()`等)
2. mailto共有機能の件名・本文組み立てロジック
3. 印刷/PDF出力のレイアウト内の見出し・メタ情報表示
4. 自動事前調査(重大アラート検知時)が生成する要約・クエリ文
5. Insight Agentに渡すシステムプロンプト・クエリの前処理(現状「日本語で回答して」等の強制指定が無いことも含めて再確認する)
6. その他、上記に類する「テンプレート文字列に変数を埋め込んで組み立てている」箇所

それぞれについて、実装ファイル・関数名・現在の組み立てロジックの概要を記録する。

### Task 3: 各タブの文言量の概算

タブごとに(1)静的ラベルの件数、(2)動的生成文の箇所数、を概算し、後続の実装指示ファイルをタブ単位で分割する際の作業量の目安にする。

### Task 4: 棚卸し結果のまとめ

1. `instructions/28_findings.md`に、Task 1〜3の結果を一覧化してまとめる(ファイル単位・タブ単位で参照しやすい形式にする)
2. 静的ラベルの総数、動的生成文の総数、レイアウト崩れが懸念される箇所の一覧を、完了報告の冒頭でサマリーとして示す

## 完了報告

verified-report形式で報告すること。特に:

- 静的ラベルの総数(タブ別内訳)
- 動的生成文の一覧(箇所・概要)
- レイアウト崩れが懸念される箇所の一覧
- 後続の実装指示ファイルの分割案(あれば所見として提示してよいが、最終決定はユーザーと相談してから行う)

このタスクでは実装・コード変更・`docker compose`の再ビルド等は行わない。git操作も行わない。

**推奨モデル: Opus**(文言の分類・動的生成文の特定・レイアウト崩れの所見など判断を伴う調査タスクのため)
