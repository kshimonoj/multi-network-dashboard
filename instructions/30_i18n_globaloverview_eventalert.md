# 30: Global Overview + Event/Alertタブの辞書化 + BOTH_PLATFORMS_RULEの文言強化

## 前提

29番でi18n基盤(Context・辞書・言語切替UI・永続化)は構築済み。`src/i18n/ja.json`・`en.json`にキーを追加し、対象コンポーネントで`t()`経由の表示に置き換えていく方式を踏襲する。

## タスク

### Task 1: Global Overviewタブの辞書化(146件)

1. `instructions/28_findings.md`のGlobal Overview区分(UI文言112件+srv→UI 34件)を対象に、`ja.json`/`en.json`にキーを追加し、該当コンポーネントを`t()`経由の表示に置き換える
2. サーバー側からクライアントに渡される文言(srv→UI 34件、例: エラーメッセージや欠損値の説明文言)については、サーバー側でハードコードせず、クライアント側で受け取った状態コードやフラグをもとに`t()`で組み立てる形に変更できないか検討する。サーバー側の応答形式自体を大きく変える必要がある場合は、無理に対応せず現状維持でよい(完了報告に理由を明記すること)
3. 28番で指摘されたレイアウト崩れ懸念(L-2: 重要度列70px、L-3: 操作列84px、L-9: 共有テキストの全角スペース手動整列)について、英語表示時に実際に崩れるか確認し、崩れる場合は幅の調整等を行う

### Task 2: Event/Alertタブの辞書化(78件)

1. 同様に、Event/Alert区分(UI文言50件+srv→UI 28件)を辞書化する
2. 28番のL-5(曜日ボタン7個)について、英語表示時の文字量を確認し、必要であれば幅を調整する

### Task 3: BOTH_PLATFORMS_RULEの文言強化(i18n辞書化とは別件)

29番で判明した「モデルがSKIP宣言を出さずに片方のプラットフォームを無言で省略するケースがある」問題への対応。

1. `insight-agent.ts`のsystem prompt内、`BOTH_PLATFORMS_RULE`に相当する箇所(両プラットフォームを扱う際の指示文)を確認する
2. 「調査対象から一方のプラットフォームを省略する場合は、必ず`[SKIP:platform]`マーカーを使って明示的に宣言すること」という趣旨の文言を、既存の指示より強く・明確に(例: 箇条書きの先頭に置く、「必ず」等の強調語を使う)修正する。日本語版・英語版の両方に同様の強化を行う
3. 修正後、いくつかの実クエリ(片方のプラットフォームが明らかに関係ないと判断されるべき質問)を試し、SKIP宣言の遵守率が改善したか確認する。完璧な遵守を保証することはできないため、「改善したかどうか」の所感を報告すればよい(数値的な保証は不要)

### Task 4: 動作確認

1. Global Overview・Event/Alertタブで日英切替を行い、表示が正しく切り替わることを確認する
2. レイアウト崩れ懸念箇所(Task 1・2で対応したもの)が英語表示で崩れていないことを確認する
3. Task 3のBOTH_PLATFORMS_RULE強化後、SKIP宣言の遵守状況を確認する
4. 既に辞書化済みの共有/シェル部分、および未着手のタブ(Webhookログ・Streaming・ネットワーク調査)の表示に影響が無いことを確認する
5. ダークモード両テーマでの表示を確認する
6. `docker compose up -d --build`で反映し、実画面を確認する
