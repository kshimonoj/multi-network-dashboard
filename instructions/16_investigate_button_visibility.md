# 16: EventFeedの「調査する」ボタンの視認性改善(multi-network-dashboard)

## 背景

15番で追加したEventFeed(Event/Alertタブ)の「調査する」列がテーブル右端にあり、本文が長い行では横スクロールしないと見えず見つけにくい。

## タスク

1. 「調査する」列を、横スクロールしても常に見える位置に固定する。既存の`.go-dp-scroll`等で使っているsticky実装のパターンを参考に、この操作列を`position: sticky; right: 0;`(テーブルが横スクロールする場合)にして、スクロール位置に関わらず常に見える状態にする
2. 背景色は行の背景と衝突しないよう、テーマ変数(`--panel`等)を使って列の背景を明示的に塗り、下の内容が透けて見えないようにする
3. 別案として、列自体を右端に置くのではなく、視認性を優先してテーブル左端(サイト名やチェックボックス等の直後)に移動する案も検討してよい。実装のしやすさ・既存レイアウトへの影響を見てどちらか判断する
4. サイト詳細ページ(SiteDetailPage.tsx)側のアラート/イベント項目の「調査する」ボタンは、そもそもテーブルではなくカード/リスト形式のはずなので、同様の視認性問題が無いか確認し、あれば同様に改善する
5. ダークモード両テーマで、固定した列がスクロール時にも正しく表示され続けることを確認する
6. `docker compose up -d --build`で反映し、実画面(実際に横スクロールさせて)で確認する

## 完了報告

verified-report形式で簡潔に報告すること。採用した方式(sticky化 or 列移動)とその理由、実際に横スクロールさせた際の見え方、ダークモードでの確認結果、`docker compose up -d --build`後の反映確認結果を含めること。

git操作は行わないこと。
