# 54: Mist側確認 + 本番コンテナ反映

## 背景(51〜53番からの引き継ぎ)

- 51番でCentral/Mist両対応の実行エンジン・API、52番でタブUI、53番で結果一覧の展開表示+ルールリファレンスページまで実装済み
- 52・53番の実機確認はいずれもローカル別ポート(8093)でのみ行っており、Mistサイトについては52番で「1_Kyobashi」の基本動作(診断実行→結果表示、unknown表示)のみ確認済み。53番で追加した展開表示・法務確認注記・AI所見注記はCentralサイトでしか確認していない
- 本番Dockerコンテナ(ポート8092)は49〜53番のコード変更を一切反映していない(rebuildしていない)

## タスク

### Task 1: Mist側での53番機能の確認(ローカル8093のまま)

1. Mistサイト(52番で使用した「1_Kyobashi」など)で「診断実行」→結果一覧を表示し、各ルールの展開表示(desc/category/priority/method/references)が正しく開けることを確認する
2. MistでunknownになるルールSEC-07〜11・RF-08〜12について、展開ブロックが崩れずに表示され、「取得できない」旨の説明が意図通り出ることを確認する
3. Mist側でrequiresLegalReview対象(SEC-10/11)・AI所見対象(SEC-12/13, RF-15/16)の展開時の注記表示を確認する(Mistでは一部unknownになるため、判定できたルールの範囲で確認する)
4. 「ルール一覧で詳しく見る」からルールリファレンスサブビューへの遷移・スクロール・ハイライトがMistサイト表示時にも同様に動作することを確認する

### Task 2: 本番コンテナへの反映

1. Mist側確認で明らかな問題が無いことを確認したら、本番環境で以下を実行する
   ```
   cd /Users/kshimono/claude/multi-network-dashboard
   docker compose up -d --build
   ```
2. 反映後、ポート8092(本番)で以下を確認する:
   - 「ベストプラクティス」タブが表示されること
   - Central・Mist双方のサイトで診断実行→結果一覧→展開表示→ルール一覧、の一連の流れが動作すること
   - 既存の他タブ(Global Overview / Event・Alert / Webhookログ / Streaming / レポート / ナレッジ)に表示・動作の影響が出ていないこと
   - ブラウザコンソールにアプリ由来のエラーが出ていないこと
   - コンテナのログにエラーが出ていないこと(`docker compose logs`)

## 制約

- 本番のSSID・WLAN設定の変更は一切行わない
- git操作は行わない(コミット等は別途指示があるまで実施しない)
- Task 1で明らかな不具合が見つかった場合は、Task 2(本番反映)を実施せず、不具合の内容を完了報告に記載して指示を仰ぐこと

## 完了報告

verified-report形式で報告すること。特に:

- Mist側での53番機能の確認結果(展開表示・unknown表示・法務確認注記・AI所見注記・ルール一覧遷移)
- 本番反映(rebuild)の実行結果とバージョン確認
- 本番ポート(8092)での動作確認結果(他タブへの影響有無を含む)
- 問題が見つかり反映を見送った場合はその内容
