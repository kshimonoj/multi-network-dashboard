# 66: Coachの画面操作混同バグの修正(CentralとMulti Network Dashboardの混同、一般論レベルへの是正)

## 背景・問題

- 65番で実装したCoachタブの壁打ちで、ヒント/質問がCentralの管理画面とMulti Network Dashboard(このアプリ自身)のUIを混同してしまう問題が見つかった
- 実際のやり取り例: 「スイッチが落ちたって連絡が来たとき、最初に何を確かめますか」という質問に対し、Coachが「ネットワーク調査タブを開いて」「Multi Network Dashboardを開いて見てる状態?」のように、**このアプリ自身の画面操作を前提にした誘導**をしてしまっていた
- Multi Network Dashboardは自作アプリで頻繁に変更されるため、画面の具体的な操作手順をヒントの中身にするのは不適切(すぐに実態と合わなくなる)
- 方針: Coachのヒント・質問は**一般的なチェック観点レベルに留める**(例:「スイッチのステータスは確認した?」「アップリンクの機器の状態は確認した?」)。CentralやMistについての具体的な知見(ナレッジ)があれば、それは使ってよい(例:「Central上のこの設定項目を見た?」)が、**Multi Network Dashboard自身の画面操作(どのタブを開く、どのボタンを押す等)を答えの一部にしてはいけない**

## タスク

### Task 1: 原因調査

1. Coachが「ネットワーク調査タブを開いて」のような回答をした経緯を、実際のログ(system prompt・取得した教材・LLMの生成過程)から特定する
2. 疑われる原因を確認する: 過去のNetwork Investigation履歴(調査ログ)の中に、「ネットワーク調査タブで確認した」のような、このアプリの画面名・UI操作に言及したテキストが含まれており、それが教材としてそのままCoachのヒントに使われてしまっている可能性がある。実際にそうなっているか確認する
3. 他にも、Best Practiceのdescription等、教材ソースの中にMulti Network Dashboard自身のUI名称が混入している箇所が無いか確認する

### Task 2: 修正方針の実装

1. Coachのsystem promptに、明確な禁止事項を追加する: 「Multi Network Dashboard(このアプリ)自身の画面・タブ・ボタン等のUI操作を回答やヒントに含めてはいけない」という指示を明記する
2. 教材(ナレッジ・調査履歴・ベストプラクティス)から取得したテキストに、このアプリのUI名称(タブ名等)への言及が含まれる場合、Coachがそれをそのままヒントとして出力しないよう、生成時にフィルタ・言い換えをする仕組みを検討する(単純にプロンプト指示だけで抑制しきれるか、後処理での検出も必要かを判断する)
3. ヒント・質問の既定のトーンを「一般的なチェック観点」に寄せる。例えば「まず何を確認しますか」に対する模範的なヒントの形は「スイッチのステータスは確認しましたか」「アップリンクの機器の状態は確認しましたか」のような、機器・現象に着目した一般論であり、「どの画面を開くか」ではないことをプロンプトに明記する
4. Central/Mistの具体的な知見(承認済みナレッジ等)がある場合は、それを使った具体的な言及(Central上の設定項目名等)は許容してよいことも明記する(禁止するのはMulti Network Dashboard自身のUIへの言及のみ)

### Task 3: 動作確認

1. 添付されたやり取りに近い質問(「スイッチが落ちたって連絡が来たとき、最初に何を確かめますか」等)で壁打ちを行い、Multi Network Dashboardの画面操作に言及しないことを確認する
2. Central/Mistの具体的なナレッジがある場合には、それを使った具体的なヒントが出せることも確認する(禁止が過剰になっていないか)
3. いくつかの異なる話題(スイッチ障害・無線障害・セキュリティ関連等)で壁打ちを行い、いずれも一般論レベルのチェック観点でヒントが出ることを確認する
4. hintLevelの段階的開示・エスカレーション・クイズモードなど、65番で実装した既存機能に副作用が出ていないことを確認する

## 制約

- Central/Mistの設定変更は一切行わない
- git操作は行わない(コミット等は別途指示があるまで実施しない)
- 65番で実装済みの機能(hintLevel管理、refCount汚染防止、根拠リンク等)を壊さないこと

## 完了報告

verified-report形式で報告すること。特に:

- 原因調査の結果(何がMulti Network DashboardのUIに言及する原因だったか)
- 修正内容(system prompt・フィルタ処理等)
- 添付の質問例を含む複数話題での動作確認結果
- Central/Mist知見を使った具体的な言及が禁止しすぎになっていないことの確認結果
