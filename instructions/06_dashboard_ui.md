# 06: Central/Mist直接APIダッシュボードのフロントエンドUI(multi-network-dashboard)

## 前提・背景

05番でバックエンド(`GET|POST /api/global-overview/{snapshot,summary,sites,status,refresh}`、GETはキャッシュ読みのみで外部APIを叩かない)が完成している。今回はこのデータを表示する新タブのUIを実装する。

- Central「Active」アラートとMist「直近24時間」アラームは定義が異なるため、UI上でラベルを明確に分けること(例: 「Active」「過去24h」等、混同されない表記)
- Mistのサイト健全性スコアはnull(未取得)であることをUI側でも考慮し、値がない場合の表示(「—」等)を用意すること
- デザインは一任。参考画像(NetView Multi-Vendor Dashboard)と同等以上を目指しつつ、Global OverviewにMAP表示を追加する

## タスク

### Task 1: タブ/ナビゲーションの実装

1. 既存の調査ページ(network-investigation)と、新設するダッシュボードページを切り替えられるようにする。ルーティングライブラリを新規導入するほどの複雑さは不要なので、アプリ内のタブ切り替え(ローカルstateでの表示切り替え)で構わない
2. ダークモード切り替え・テーマ(`theme.css`)は両画面で共通のものを使う

### Task 2: Global Overview画面の実装

参考画像のレイアウトを踏襲しつつ、以下を含める:

1. **Global Summary**: 総サイト数、総デバイス数(内訳: Up/Down)、総接続クライアント数、アクティブアラート数(合計)のカード表示
2. **プラットフォーム別パネル**(HPE Aruba Central / Juniper Mist): サイト数、クライアント数、アラート数(それぞれの定義でのラベルを明記)、AP/Switch/Gatewayのドーナツチャート(Up/Down内訳)
3. **サイト別内訳テーブル**: サイトごとのAP/Switch/Gateway状況、クライアント数、アラート数
4. **MAP表示**: 参考画像には無い要素として新規追加。site-map.tsの緯度経度情報を使い、Leaflet(既存依存を流用)でサイトをピン表示する。ピンの色や状態表示は、Central/Mistのプラットフォームや稼働状況(Up/Down/アラートの有無)が視覚的に分かるようにする
5. Mistの健全性スコアがnullの場合は「—」等で欠損値であることが分かる表示にする(0や空欄で誤解を招かないこと)

### Task 3: データ取得・更新

1. 画面表示時に`GET /api/global-overview/snapshot`(または該当エンドポイント)からキャッシュ済みデータを取得して表示する
2. 手動更新ボタンを設置し、`POST /api/global-overview/refresh`を呼び出す(05番で実装済みの60秒間隔ガードにより連打しても外部APIを叩かないことを踏まえた上で、UI側でも連打防止の見た目のフィードバック(ボタンの一時無効化等)を入れる)
3. 最終更新時刻を画面に表示する

### Task 4: 動作確認

1. 実際にタブを切り替えて両画面(調査ページ/新ダッシュボード)が問題なく動作することを確認する
2. ダークモード切り替えが新ダッシュボードにも正しく反映されることを確認する
3. MAPが実データ(22サイト)で正しく表示されることを確認する
4. `docker compose up -d --build`で反映し、`/health`と実画面を確認する
