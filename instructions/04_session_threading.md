# 04: 「続けて調べる」のセッション化 + 一気通貫表示 + 共有/報告の拡張(multi-network-dashboard)

## 前提・背景

現状、「続けて調べる」を繰り返した場合の各回答が`data/network-investigation/query-history.jsonl`にどう保存されているか(セッションとしての紐付けがあるか、単に時系列のフラットな列として保存されているだけか)が未確認。B-11として、まず現状のデータ構造・フロントエンドの「続けて調べる」実装を調査してから設計する。

## タスク

### Task 1: 現状調査(設計前に必ず実施)

1. `query-history.jsonl`の各レコードのスキーマを確認する(フィールド一覧、`site`指定の有無、タイムスタンプ、実行結果等)
2. フロントエンド側で「続けて調べる」を押したときの実装を確認する: 前回の回答・会話コンテキストをどう次のclaude CLI呼び出しに渡しているか(subprocessへの引き継ぎ方法)、そのやり取りがサーバー側の保存データに何らかの紐付けフィールド(親クエリID等)として残っているか、それとも紐付けはフロントエンドのReact stateの中だけに存在し、サーバー保存時には失われているか
3. 履歴詳細画面(`.ni-detail-block`)が現在、連続した「続けて調べる」の回答をどう表示しているか(現状バラバラに表示されているのか、簡易的にでも繋がりを見せているか)を確認する
4. 調査結果を`instructions/04_findings.md`に記録する

### Task 2: セッションデータモデルの設計・実装

Task 1の結果を踏まえて、以下の方針で実装する(調査の結果、既に紐付けの仕組みがある場合はそれを活かし、無理に新設計を追加しないこと):

1. 「続けて調べる」で生成された一連の回答をグルーピングするための`sessionId`(初回クエリ発行時に生成)を、`query-history.jsonl`の各レコードに追加する
2. 既存の(セッション化以前の)履歴データには`sessionId`が存在しないため、読み込み側は「`sessionId`がなければ単独セッションとして扱う」形で後方互換を保つ
3. サーバー側に、指定した`sessionId`に属する一連のレコードを時系列順に返すAPIエンドポイントを追加する

### Task 3: 一気通貫表示UI

1. 履歴一覧画面から、同一セッションに属する複数の回答を1つのスレッドとしてまとめて表示する画面(または既存の履歴詳細画面の拡張)を実装する
2. 各ターン(1回のクエリと回答)を区別できるように表示しつつ、スクロールして連続して読める構成にする
3. 実行中(SSEでの可視化)の画面から「続けて調べる」した場合も、そのままこのスレッド表示に追加されていく形にする

### Task 4: 共有・報告機能をセッション全体に拡張

03/03b番で実装した共有・報告機能(印刷/PDF・mailto・クリップボードコピー)を、単発の回答だけでなく**セッション全体(一連のスレッド)**に対しても使えるようにする。

1. 印刷/PDF: セッション内の全ターン(クエリ・回答・chart/topologyを含む)を、既存の`printClone.ts`の仕組みを使って連結した印刷ツリーとして出力する。ターンの区切りが分かるよう見出し(実行時刻等)を挟む
2. mailto: セッション全体を要約してから本文に入れる(全ターンをそのまま入れると文字数超過が確実なため、各ターンの要点を短くまとめた要約を生成し、詳細はダッシュボードで確認する旨を添える)
3. コピー: セッション全体のプレーンテキスト版をクリップボードにコピーできるようにする

### Task 5: 確認と反映

1. 実際に「続けて調べる」を2〜3回連続で行い、セッションとして正しくグルーピング・表示されることを確認する
2. 単独クエリ(1回のみ)の場合も従来通り問題なく表示・共有できることを確認する(後方互換の確認)
3. `docker compose up -d --build`で反映し、`/health`と実画面を確認する

## 完了報告

verified-report形式で報告すること。特に:

- Task 1の調査結果(既存の紐付け有無)とそれを踏まえた設計判断の理由
- セッション化後も既存の単独クエリ履歴が問題なく表示されるか(後方互換)
- セッション全体の印刷/PDF・mailto・コピーの動作確認結果
- `docker compose up -d --build`後の反映確認結果

git操作は行わないこと。
