# 08: 失敗の可視化(個別ツール呼び出しのエラー詳細表示 + 全体障害時のUI検証)

## 背景

ネットワーク調査ページで、一部のMCPツール呼び出し(例: `get_mist_insights`, `get_mist_config`)が失敗と表示されるが、その行をクリックしても詳細(エラーコード・メッセージ)が展開されず、失敗理由を画面から確認できない。これでは「サイト/組織がそのライセンス・権限を持っていないための想定内の制限」なのか「実装上のバグ」なのかをユーザーが判断できない。

あわせて、06番のNEXTで挙がっていた「Central/Mistの認証情報を意図的に無効化した場合の障害時表示」も未検証のままなので、今回まとめて対応する。

## タスク

### Task 1: 個別ツール呼び出しの失敗理由をUIで確認できるようにする

1. SSEでツール呼び出し結果を流している箇所(mcp.ts/insight-agent.ts)で、失敗時(`is_error: true`相当)に実際のエラーメッセージ・ステータスコードがどこまで保持されているか確認する(claude CLIの出力に含まれているか、含まれていれば現状どこで捨てられているか)
2. 保持されているエラー情報を、失敗した行をクリックした際に展開して表示するUIを実装する(400/403/500等のステータスコードとエラーメッセージ本文を表示する)
3. 実際に失敗しているツール呼び出し(現状再現している`get_mist_insights(insight_type=sle)`等)で、展開した内容が実際に意味のある情報(ライセンス不足なのか、パラメータ不正なのか等)を示しているか確認する

### Task 2: 個別ツール失敗の原因調査(副次的に判明したら記録)

Task 1の実装過程で、現在実際に失敗している`get_mist_insights(insight_type=sle)`・`get_mist_config`の失敗理由が判明した場合は、`instructions/08_findings.md`に記録する(想定内の制限かバグかの切り分け)。この原因調査自体を目的化しすぎず、Task 1のUI実装に必要な範囲で行えばよい。

### Task 3: 全体障害時(認証情報無効)のUI検証

1. Central/Mistの認証情報を一時的に無効化した状態(意図的に壊した`.env`のコピー等、本番の`.env`は変更しない)で、以下を確認する:
   - ネットワーク調査ページでInsight Agentを実行した場合の失敗表示
   - Global OverviewでCentral/Mist直接APIの取得が失敗した場合のパネル表示(「取得失敗」タグ・エラーメッセージ)
   - スナップショット自体が存在しない場合(503相当)の初期表示
2. 検証後は必ず本来の認証情報に戻し、正常動作することを確認する

## 完了報告

verified-report形式で報告すること。特に:

- 個別ツール呼び出しの失敗理由がUIから確認できるようになったか(実際の表示例を添えて)
- 現在再現しているMist側の失敗(`sle`, `get_mist_config`)の原因が判明したか
- 認証情報無効化時の各画面(調査ページ/Global Overview/503相当)の表示確認結果
- 検証後に本来の認証情報へ復元し正常動作することの確認

git操作は行わないこと。
