# 31: Webhookログタブの辞書化

## 前提

29番・30番で確立したパターン(`src/i18n/ja.json`/`en.json`への名前空間追加 + `t()`経由の表示)を踏襲する。

## タスク

### Task 1: Webhookログタブの辞書化(111件)

1. `instructions/28_findings.md`のWebhookログ区分(UI文言79件+srv→UI 32件)を対象に、`ja.json`/`en.json`に`webhookFeed.*`名前空間を追加し、該当コンポーネント(WebhookFeed.tsx等)を`t()`経由の表示に置き換える
2. ソース種別のバッジ(New Central/Classic Central/Mist/GLP)、重要度ラベル、ポーリング間隔設定UI(1分〜24時間の選択肢)、「自動調査あり」「調査結果を見る」「調査する」等のボタン類を辞書化する
3. srv→UI文言(32件)は、30番と同様の判断基準(汎用的なエラー伝播経路に埋め込まれているものは現状維持でよい)で対応する。対応した場合・見送った場合、それぞれ理由を記録する

### Task 2: レイアウト崩れ懸念の確認

1. 28番のfindingsにWebhookログタブに関するレイアウト崩れ懸念があれば(前回30番でL-5/L-9が実は別タブだったと判明した経緯があるため、今回も対象ファイルが本当にWebhookログタブのものか事前にgrep等で確認してから着手すること)、英語表示で実際に確認し、必要であれば調整する
2. 特に自動事前調査の要約表示・「調査結果を見る」導線まわりは、英語化で文字量が増えてボタン等が窮屈にならないか確認する

### Task 3: 動作確認

1. Webhookログタブで日英切替を行い、全要素が正しく切り替わることを確認する
2. ポーリング間隔設定・イベント種別フィルタ等の操作系が、英語表示でも問題なく機能することを確認する
3. 既存の辞書化済みタブ(共有/シェル・Global Overview・Event/Alert)、未着手タブ(Streaming・ネットワーク調査)への影響が無いことを確認する
4. ダークモード両テーマでの表示を確認する
5. `docker compose up -d --build`で反映し、実画面を確認する
