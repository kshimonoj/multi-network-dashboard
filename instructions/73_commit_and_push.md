# 73: 66〜75番の変更をコミット・GitHubへpush

## 背景

- 66〜72番でCoach機能の改善(画面操作混同修正・エスカレーション/相槌バグ修正・ライブMCP追加・速度改善・履歴閲覧UI)とKnowledgeの重複検出機能を実装し、73番作成時点で本番(8092)で動作確認済み(72番)
- その後追加で74番(クイズの「答えが欲しい」ボタンの誤認識修正)・75番(壁打ち例文のランダム抽出化)も実装・本番反映済み。73番のコミット対象はこれらも含めた66〜75番全体とする
- 55番・63番と同様、push前のセキュリティ監査を必須とする

## タスク

### Task 1: 変更内容の棚卸し

1. `git status`で66〜75番による変更ファイル一覧を確認する(想定: `plugins/coach/`一式、`plugins/knowledge/dedupe.ts`等の新規ファイル、`plugins/network-investigation/`関連、`server/index.ts`、`src/i18n/`、`src/main.tsx`、`src/shell.tsx`、`Dockerfile`、`docker-compose.yml`、74番のクイズreveal修正関連、75番の例文プール関連等)
2. `instructions/`配下の66〜75番の指示ファイル・findingsファイルが揃っているか確認する(既存の運用通り、`instructions/`は追跡対象)

### Task 2: セキュリティ監査(必須、push前に完了させること)

1. `git diff`全体と新規ファイル全体を対象に、以下が含まれていないことを確認する:
   - 実際のサイト名・SSID名・デバイス名・MACアドレス等の実データ
   - APIトークン・パスワード・RADIUS共有シークレット等の秘匿情報
   - 顧客名・組織名等、公開を意図していない固有名詞
2. 特に以下は重点的に確認する:
   - `plugins/coach/`配下(壁打ちの会話ログ・弱点データ・ライブMCP問い合わせ結果を扱うため、テストデータに実データが紛れていないか)
   - `plugins/knowledge/dedupe.ts`等(71番でナレッジの実データ(rogue AP関連等)を扱った経緯があるため)
   - `instructions/66〜72_findings.md`(調査中に扱った実データが伏字化されずに残っていないか)
3. 55・63番で過去に実データ混入(サイト名等)が見つかった実績があるため、同種のパターンがないか特に注意する
4. 問題があれば伏字化・除外してから次に進む

### Task 3: コミット

1. 論理的にまとまった単位でコミットを分ける(目安: Coachの画面操作混同修正+状態管理修正(66・67番)、ライブMCP追加(68番)、JA_SYNONYMS修正等(69番)、Coach速度改善・履歴UI・対話バグ修正(70番)、Knowledge重複検出(71番)、クイズreveal修正(74番)、壁打ち例文ランダム化(75番)、instructions/ドキュメント、のように分ける。まとめすぎず、後から追いやすい粒度を優先する)
2. コミットメッセージは何を実装・修正したかが分かる内容にする

### Task 4: push

1. `git push origin main`でGitHubリポジトリに反映する
2. push後、GitHub上でファイル一覧・差分を確認し、意図しないファイル(機密情報や個人環境固有のパス等)が含まれていないことを再確認する

## 制約

- pushする前に必ずTask 2のセキュリティ監査を完了させること。監査で疑わしい内容が見つかった場合は、pushを止めて内容を報告し指示を仰ぐこと
- 本番のSSID・WLAN設定の変更は行わない(このタスクの範囲外)

## 完了報告

verified-report形式で報告すること。特に:

- コミットした単位ごとのファイル一覧とコミットメッセージ
- セキュリティ監査の実施内容と結果(問題を見つけて対処した場合はその内容)
- pushが成功したことの確認(GitHub上での確認結果含む)
