# 15: Event/Alertからネットワーク調査タブへの連携(multi-network-dashboard)

## 方針

Global Overview側(直接API)で見ているイベント/アラートの内容を、MCP調査ページ(Insight Agent)に手動コピペせず渡せるようにする。「この件を調査する」的な導線を追加し、押すとネットワーク調査タブに切り替わり、その事案の要約を踏まえたクエリ文が入力欄に事前入力された状態になる。**自動実行はしない**(文面を用意してタブを切り替えるところまで。実行するかどうかはユーザーが判断する)。

## タスク

### Task 1: アプリ全体で共有する「調査キュー」の仕組み

1. 既存のタブシェル(main.tsx、ローカルstate方式)に、「ネットワーク調査タブに渡す事前入力クエリ」を一時的に保持する軽量な共有state(例: `pendingInvestigationQuery`)を追加する
2. ネットワーク調査タブのコンポーネント(NetworkInvestigation.tsx)は、この共有stateに値がセットされている場合、入力欄にその値を反映し、可能であればサイト選択も対応するサイトに合わせる(サイト名が特定できる場合)。反映後は共有stateをクリアする

### Task 2: Event/Alertタブでの「調査する」ボタン

1. Event/Alertタブの各行(または展開時の詳細)に「調査する」ボタンを追加する
2. 押すと、その事案の要約(サイト名、プラットフォーム、重要度、カテゴリ、発生時刻、メッセージ本文)を人が読める形の日本語クエリ文として組み立て、Task 1の共有stateにセットし、ネットワーク調査タブに切り替える。クエリ文の例: 「[サイト名]で発生した以下のイベント/アラートについて、原因や影響範囲を調査して: [重要度] [カテゴリ] [メッセージ] ([発生時刻])」のような形で構わない(実装側で自然な文面にしてよい)
3. サイト名が対応表に存在する場合は、ネットワーク調査タブのサイト選択も自動でそのサイトに合わせる

### Task 3: サイト詳細ページのAlert/Eventセクションでも同様に対応

1. 11-13番で実装したサイト詳細ページ(SiteDetailPage.tsx)内のアラート/イベント一覧にも、同様の「調査する」ボタンを追加する
2. Task 2と同じ仕組み(共有stateへのセット、タブ切り替え、サイト自動選択)を流用する

### Task 4: 動作確認

1. Event/Alertタブおよびサイト詳細ページの両方から「調査する」を押し、ネットワーク調査タブに切り替わって適切な文面・サイト選択がされることを確認する
2. 実際にその文面のまま実行し、Insight Agentが違和感なく回答できることを確認する
3. 何もセットされていない通常のタブ切り替え(手動でネットワーク調査タブをクリックする等)には影響がないことを確認する
4. ダークモード両テーマでの表示を確認する
5. `docker compose up -d --build`で反映し、実画面を確認する

## 完了報告

verified-report形式で報告すること。特に:

- 実際に生成されるクエリ文の例(スクリーンショットまたはテキスト)
- Event/Alertタブ・サイト詳細ページ両方からの動作確認結果
- 生成された文面での実行結果(Insight Agentが意味のある回答を返せているか)
- 既存の通常のタブ切り替えに影響がないことの確認
- `docker compose up -d --build`後の反映確認結果

git操作は行わないこと。
