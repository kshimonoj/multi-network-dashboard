# 19: pendingHistoryFocusのタイムアウトフォールバック(multi-network-dashboard)

## 背景

18番で実装した「調査結果を見る」ボタンは、該当runIdの実行履歴がhistoryに見つかるまで待ち続ける実装になっている。該当runIdが何らかの理由でhistoryに存在しない場合(稀だが、自動調査完了直後の書き込み失敗等)、ボタンを押してもネットワーク調査タブに切り替わるだけで何も開かず、ユーザーには無反応に見えてしまう。

## タスク

1. `NetworkInvestigation.tsx`の`pendingHistoryFocus`を処理しているuseEffectに、一定時間(例: 5秒程度)待っても該当runIdがhistory内に見つからない場合のタイムアウト処理を追加する
2. タイムアウトした場合、「この調査結果は見つかりませんでした」といった趣旨の軽いメッセージ(トースト通知、または画面内の一時的なバナー等、既存のUI部品のパターンに合わせてよい)を表示する
3. タイムアウト後は`pendingHistoryFocus`をクリアし、無限に待ち続ける状態を解消する
4. 正常時(該当runIdが見つかる場合)の既存の動作に影響がないことを確認する
5. 意図的にhistoryに存在しないrunIdを`pendingHistoryFocus`にセットする(テスト用に一時的にコードで注入する、または他の方法で構わない)ことで、タイムアウト・メッセージ表示・状態クリアが正しく動作することを確認する
6. ダークモード両テーマでの表示を確認する
7. `docker compose up -d --build`で反映し、実画面を確認する

## 完了報告

verified-report形式で簡潔に報告すること。タイムアウトの実際の動作確認結果(意図的に存在しないrunIdを使った検証を含む)、正常系への影響がないことの確認、`docker compose up -d --build`後の反映確認結果を含めること。

git操作は行わないこと。

**推奨モデル: Sonnet**(既存のuseEffectにタイムアウト処理を1つ足すだけの、判断を伴わない機械的な実装のため)
