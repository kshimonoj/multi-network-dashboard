# 25: ローカルLLM(Ollama/gemma4:12b)をネットワーク調査のモデル選択肢に追加

## 前提・確定事項

- 目的はCloud Claudeとローカル・貧弱ハードウェアのLLMとの品質比較。本格的な生産機能ではなく、まず実用に足るかを見極める位置づけ
- モデルはOllamaの`gemma4:12b`(2026年4月リリース、Gemma 4系はネイティブtool calling対応、32GBメモリなら12bクラスも快適に動作)を第一候補とする
- モデル選択肢に「Local(Ollama gemma4:12b)」を追加し、Opus/Sonnetと同様に**単独で選んで実行できる**ようにする
- 加えて「比較モード」をオプションのチェックボックスとして用意し、ONの場合のみ同じクエリをClaude(選択中のモデル)とローカルモデルの両方に投げて結果を並べて表示する。比較モードは必須機能ではない

## タスク

### Task 0: Ollamaのセットアップ

1. Ollamaがインストールされていなければ`brew install ollama`でインストールし、起動する
2. `ollama pull gemma4:12b`でモデルを取得する
3. `ollama list`でモデルが利用可能になっていることを確認する

### Task 1: tool calling精度の軽い検証(本格実装前に必ず行う)

1. Ollamaの`/api/chat`(またはOpenAI互換エンドポイント)に対し、ダミーの単純なツール定義(例: 天気を返すだけのツール)を1つ渡し、実際に`gemma4:12b`が正しい形式でtool_callsを返せるか確認する
2. 次に、既存のcentral-mcp/mist-cloudのツール定義のうち1つ(例: `central_get_summary`)を渡し、実際に呼び出しを試みさせる。ツールの選択・パラメータの組み立てが妥当かを確認する
3. 明らかに実用に耐えないレベル(ツールを全く呼ばない、毎回不正なJSON、無関係なツールを選ぶ等)であれば、その旨を完了報告で明記し、Task 2以降への進行可否を判断材料として提示する。実装を続けるかどうかはユーザーの判断を仰ぐこと(Task 1の結果が悪くても独断で中止しない。ただし結果は正直に報告すること)

### Task 2: MCPクライアント + ツール呼び出しループの実装

1. `@modelcontextprotocol/sdk`のクライアントを使い、既存のcentral-mcp/mist-cloudサーバーに接続する薄いモジュールを新設する(既存のnetwork-investigationプラグインが使っているMCPサーバー定義を流用してよい)
2. Ollamaの`/api/chat`にtools定義を渡し、返ってきた`tool_calls`を実際にMCPサーバーに投げて結果を得て、モデルに再度渡す、というループを実装する(数ターンで完了しない場合の上限回数を設ける)
3. 既存のInsight Agent(claude CLI版)と同様に、呼び出したツールの一覧・実行結果をSSEやログとして可視化できるようにする(既存のUIコンポーネントを流用してよい)

### Task 3: モデル選択UIへの追加

1. ネットワーク調査タブのモデル選択(現状Opus/Sonnet)に「Local(gemma4:12b)」を追加する
2. 選択して実行すると、Task 2で実装したOllama経由のツール呼び出しループが使われるようにする
3. 「比較モード」のチェックボックスを追加する。ONの場合、同じクエリをClaude(選択中のモデル)とローカルモデルの両方に投げ、結果を並べて(または上下に)表示する。OFFの場合は選択中のモデル単独で実行する(既存の挙動と同じ)

### Task 4: 動作確認

1. Task 1で確認した精度を踏まえ、実際に何らかの実用的なクエリ(既存の調査タブで使っているような質問)をローカルモデル単独で実行し、結果の妥当性を確認する
2. 比較モードをONにして、Claude/ローカルモデル双方の結果が正しく並べて表示されることを確認する
3. 比較モードOFF時に、既存のClaude(Opus/Sonnet)単独実行の挙動に影響が無いことを確認する
4. ダークモード両テーマでの表示を確認する
5. `docker compose up -d --build`で反映し、実画面を確認する

## 完了報告

verified-report形式で報告すること。特に:

- Task 1の精度検証結果(正直な評価。実用に耐えるレベルかどうか)
- 実装したMCPクライアント・ツール呼び出しループの概要
- モデル選択・比較モードの動作確認結果
- ローカルモデル単独実行での実際の回答例と、その品質についての所感
- `docker compose up -d --build`後の反映確認結果

git操作は行わないこと。
