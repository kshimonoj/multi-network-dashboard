# 67: Coachの2つの既知課題を調査・修正(エスカレーション時の根拠欠落/短い相槌での話題リセット)

## 背景

- 65番の完了報告で申し送りとして挙げられ、66番でも改めて「別タスクとして扱うか判断してほしい」とされていた、Coachタブの2つの既知の挙動を今回まとめて対応する
- 66番でCoachの画面操作混同バグ(自アプリUI言及)は修正済み。今回はそれとは別の課題

## タスク

### Task 1: エスカレーション時に根拠(教材リンク)が空になる問題

1. エスカレーション導線(「もう答えを教えて」ボタン)経由の回答生成ルートを特定し、通常のヒント生成ルートと処理が分岐しているかどうかを確認する
2. 根拠へのリンク提示(64/65番で実装した、ヒントの元になったナレッジ・調査結果・ベストプラクティスへのリンク)の処理が、エスカレーション時のルートに組み込まれていない・スキップされているなど、原因を特定する
3. 原因を修正し、エスカレーション経由の回答でも通常のヒントと同様に根拠リンクが付与されるようにする
4. マーカー方式([SRC:...]等)や66番で追加したAPP_UI_RULES・自アプリUI言及ガードとの整合性が崩れていないか確認する

### Task 2: 短い相槌で話題(hintLevel等)がリセットされる問題

1. 学習者が「はい」「なるほど」「OK」等の短い相槌のみを送った際に、Coach側がどう処理しているかを実際のログ・コードから確認する
2. hintLevel・3ターン規則のカウント状態が意図せず0にリセットされる原因を特定する(短文が「新規トピックの質問」と誤認識されている可能性が高いという申し送りの仮説を検証する)
3. 原因を修正し、短い相槌は文脈継続として扱われ、hintLevel・ターンカウントが保持されるようにする
4. 一方で、本当に話題が変わった場合(学習者が明確に別の質問を始めた場合)は正しく新規トピックとして扱われる必要がある。相槌と新規質問の区別のロジックを検討し、既存の他の判定(例えば話題キーの一致判定、66番で追加した検出器等)との整合性も確認する

### Task 3: 動作確認

1. Task 1: 壁打ちで数ターン進めた後にエスカレーションし、根拠リンクが表示されることを確認する
2. Task 2: 壁打ち中に短い相槌(「はい」「なるほど」「OK」等、日英両方)を複数回挟んでも、hintLevel・ターンカウントが継続することを確認する
3. Task 2の裏付けとして、実際に新規トピックへ切り替えた場合は正しくリセットされることも確認する(区別ロジックの過剰修正がないか)
4. 66番で実装したガード機構(自アプリUI言及の検出・言い直し)に副作用が出ていないことを確認する
5. hintLevel・エスカレーション・クイズモードなど、既存機能全体に回帰が無いことを一通り確認する

## 制約

- Central/Mistの設定変更は一切行わない
- git操作は行わない(コミット等は別途指示があるまで実施しない)
- 65・66番で実装済みの機能を壊さないこと

## 完了報告

verified-report形式で報告すること。特に:

- Task 1・Task 2それぞれの原因調査結果と修正内容
- 動作確認の結果(相槌と新規トピックの区別が適切に機能しているかを含む)
- 66番のガード機構への副作用有無
- 未確認・次回に持ち越した事項
