# 03b: 印刷/PDF出力にグラフ・トポロジーを含める(03番の派生修正)

## 前提・背景

03番で実装した印刷/PDF機能は、印刷用の隠しツリーにタイトル・メタ情報・回答本文(テキスト)のみを流し込んでおり、`chart`ブロック(recharts)・`topology`ブロック(mermaid)は印刷対象に含まれていなかった。今回はこれらを印刷/PDF出力にも含める。

## 方針

- chart/topologyを印刷用に**再レンダリングしない**こと。特にrechartsが`ResponsiveContainer`を使っている場合、印刷ツリー(オフスクリーン/サイズ0の可能性がある)で再マウントすると幅0で描画が壊れる
- 対象の回答パネル内で**既にレンダリング済みのSVG DOM要素をそのままdeep cloneして印刷ツリーに挿入する**方式を採る。再レンダリングではなく複製なので、画面上の実測サイズがそのまま反映される
- mermaid(Topology.tsx)も同様に、既存のテーマ追従(MutationObserverでの再描画)ロジックは変更せず、現在描画済みのSVGをそのままクローンする

## タスク

### Task 1: 印刷ツリー生成ロジックの拡張

1. 現状の印刷ツリー構築関数(タイトル・メタ情報・回答本文を組み立てている箇所)を確認する
2. 対象回答パネル内に`chart`ブロック・`topology`ブロックが存在する場合、それぞれのレンダリング済みSVG要素(`<svg>...</svg>`)をクエリで取得し、`cloneNode(true)`で複製して印刷ツリーの該当箇所(回答本文の対応する位置)に挿入する
3. 複数のchart/topologyが1つの回答に含まれる場合、出現順を維持して挿入する

### Task 2: 印刷用CSSの調整

1. `body > #root { display:none }`の既存ルールは維持しつつ、印刷ツリー内に挿入されたSVG(chart/topology)が正しく表示されるようスタイルを調整する
2. 複数チャートがページ途中で分断されないよう`page-break-inside: avoid`(または`break-inside: avoid`)を各chart/topologyブロックのコンテナに適用する
3. SVGの幅が印刷用紙面(`@page`)に収まるよう、必要であれば`max-width: 100%`を明示する

### Task 3: 動作確認と反映

1. chart・topologyの両方を含む回答で印刷プレビュー相当の確認を行い、グラフ・図が正しく表示されることを確認する(03番と同様、ブラウザ自動化で印刷ダイアログ自体は開けないため、`@media print`ルールを画面に注入して再現する形でよい)
2. 確認後、`cd ~/claude/multi-network-dashboard && docker compose up -d --build` を実行し、稼働中コンテナ(8092番)に今回の変更(および03番の未反映分)をまとめて反映する
3. 反映後、`/health`と実画面の両方が正常に表示されることを確認する

## 完了報告

verified-report形式で報告すること。特に:

- chart/topologyが印刷ツリーに正しく複製・表示されるか
- 複数チャートがある場合のページ分割挙動
- `docker compose up -d --build`後の反映確認結果

git操作は行わないこと。
