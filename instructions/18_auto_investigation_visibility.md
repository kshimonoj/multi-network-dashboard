# 18: 自動事前調査結果の視認性改善 + ネットワーク調査タブの該当結果への直接ジャンプ

## 背景

17番で「重大アラートの自動事前調査」を実装し、Webhookログページの行を展開すると要約が表示される設計にしたが、現状は行の左端にある小さな三角ボタンをクリックしないと展開されず、見つけにくい。加えて、「その要約を見て終わり」ではなく、**実際にネットワーク調査タブ側でその自動調査が実行された履歴(スレッド)そのものに直接ジャンプして見たい**という要望がある。これは既存の「調査する」ボタン(=新しいクエリを事前入力してタブ切替するだけ)とは別の導線として必要。

## タスク

### Task 1: 行全体をクリック可能にして展開する(最優先の修正点)

1. 現状、展開のトリガーが行左端の小さな三角アイコンのみになっている。これを**行全体(バッジやリンクボタン部分を除く)をクリックすると展開/折りたたみが切り替わる**ようにする
2. 三角アイコン自体も残してよいが、視覚的な向き(▶/▼)で展開状態が分かるようにし、行にカーソルを合わせた際に「クリックできる」ことが分かるスタイル(hoverでの背景色変化やカーソル形状`pointer`等)を付ける
3. 「自動調査あり」のログには、常時見える形で明示的なバッジ(既存の「AI 自動事前調査あり」ラベルで良いが、より目立つ配色にしてもよい)を表示する
4. Task 2で追加する「調査結果を見る」ボタンなど、行内の他のクリック可能要素との**クリックイベントの競合(行クリックで展開しつつ、その中のボタンだけ個別に反応する)** に注意し、`event.stopPropagation()`等で適切に制御する

### Task 2: ネットワーク調査タブの該当履歴へ直接ジャンプする機能

1. 自動事前調査(17番のenrich.ts経由で実行されたもの)の結果には、実行時に払い出された`runId`(またはセッションID)が既に紐付いているはずなので、その値をWebhookログ側のデータにも保持・参照できるようにする
2. 15番で実装済みの共有state(`pendingInvestigationQuery`、新しいクエリをタブに渡す仕組み)とは別に、**「指定した過去の実行結果を開く」ための共有state**(例: `pendingHistoryFocus`、値は runId/sessionId)を新設する
3. Webhookログページの自動調査済み行(展開した中、または行内)に「調査結果を見る」ボタンを設置する。押すと`pendingHistoryFocus`に該当runIdをセットしてネットワーク調査タブに切り替える(このボタンのクリックはTask 1の行展開とは独立して動作すること)
4. ネットワーク調査タブ(`NetworkInvestigation.tsx`/`HistoryThread.tsx`)側で、`pendingHistoryFocus`がセットされている場合、該当する過去の実行(セッション/ターン)を自動的に開いて表示し、該当箇所までスクロールする実装を追加する。表示後は`pendingHistoryFocus`をクリアする
5. 通常のタブ切り替え(この機能を使わない場合)には影響がないことを確認する

### Task 3: 動作確認

1. Webhookログの行をクリックして(小さい三角以外の場所でも)展開/折りたたみが正しく切り替わることを確認する
2. 自動調査済みの行から「調査結果を見る」を押し、ネットワーク調査タブに切り替わって該当の過去実行結果が正しく表示されることを確認する(行展開のクリックと誤って競合しないことも確認する)
3. 「調査する」ボタン(新規クエリ事前入力)と「調査結果を見る」ボタン(既存結果へジャンプ)が混同されない見た目・配置になっていることを確認する
4. ダークモード両テーマでの表示を確認する
5. `docker compose up -d --build`で反映し、実画面を確認する

## 完了報告

verified-report形式で報告すること。特に:

- 行全体クリックでの展開/折りたたみの動作確認結果
- 自動調査結果の視認性改善の実際の見た目
- 「調査結果を見る」機能の動作確認結果(実際にジャンプして正しい過去実行結果が開くこと)
- 行展開のクリックと「調査結果を見る」ボタンのクリックが競合しないことの確認
- 「調査する」との違いが分かりやすくなっているか
- `docker compose up -d --build`後の反映確認結果

git操作は行わないこと。
