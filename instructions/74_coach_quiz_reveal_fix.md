# 74: クイズの「答えが欲しい」ボタンが空欄回答として誤って扱われる不具合の修正

## 背景・問題

- クイズ出題で「答えが欲しい」(答えを教えてほしいという明示的な要求)をクリックすると、Coachが「解答が空欄のようだね」という趣旨の応答をしてしまう
- これは、利用者が明示的に「答えを教えて」と要求しているのに、それを「空欄の回答が提出された」と誤認識している状態で、意図と応答がズレている
- 70番のTask4(壁打ちの「ヒントをもう1つ」ボタンが偽の発話として扱われ、不自然な前置きが出ていた問題)と同種のバグが、クイズの回答提出フロー(壁打ちとは別のコードパス)に残っている可能性が高い

## タスク

### Task 1: 原因調査

1. クイズの「答えが欲しい」ボタンをクリックした際に、サーバー側でどのような処理が行われているか(`plugins/coach/quiz.ts`等)を確認する
2. 70番のTask4で壁打ち側に導入した「ボタン操作は発話欄ではなく別の形(`<今回の操作>`等)で渡す」という設計が、クイズの回答提出・答え開示フローには適用されていないことを確認する
3. 「答えが欲しい」ボタンが、内部的に「空文字列の回答」としてクイズの採点ロジックに渡されており、採点ロジックが「回答が空欄」というフィードバックを生成している経路を特定する

### Task 2: 修正

1. クイズの「答えが欲しい」ボタンを、通常の回答提出(採点対象)とは明確に区別する。壁打ちのエスカレーション(70番のTask3で修正済み)と同様に、「答えを直接開示する」という専用の操作として扱う
2. 開示時の応答は、「回答が空欄だった」という体裁ではなく、素直に「答えはこうだよ」という解説から始まる内容にする(70番のTask3で壁打ちのエスカレーション開示に適用した末尾の疑問形除去等の方針との一貫性も確認する)
3. 修正時、69番・70番で対応した関連バグ(偽の発話・ボタン操作の誤認識)の他の発生箇所が無いか、Coach機能全体(壁打ち・クイズ双方の全ボタン操作)を一通り洗い出して確認する

### Task 3: 動作確認

1. クイズ出題→未回答のまま「答えが欲しい」をクリックし、「回答が空欄」という指摘なしに、素直に解説が出ることを確認する
2. 通常通り回答してから不正解だった場合の「答えを見る」の流れ(70番で修正済み)にも副作用が出ていないことを確認する
3. Task2で洗い出した他のボタン操作についても、同様の誤認識が起きていないか確認する
4. 実装完了後、本番Dockerコンテナのrebuildまで行い、本番ポート(8092)での動作確認まで実施する(標準運用ルール通り)
