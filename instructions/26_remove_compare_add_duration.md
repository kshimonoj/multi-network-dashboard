# 26: 比較モードの削除 + 実行時間のタイムライン記録(multi-network-dashboard)

## 方針

25番で実装した「ローカルモデル(gemma4:12b)と比較する」チェックボックス・2カラム比較パネルは不要と判断し削除する。代わりに、**モデルを問わず(Sonnet/Opus/Local共通)各実行の所要時間を記録し、実行タイムラインで確認できるようにする**。これにより、SonnetとLocalをそれぞれ別々に実行して、後からタイムライン上で所要時間を見比べることができる。

## タスク

### Task 1: 比較モードの削除

1. `NetworkInvestigation.tsx`から「ローカルモデルと比較する」チェックボックスと、それに伴う2カラム比較パネル(Turn/SseLogを並べて表示する仕組み)を削除する
2. 削除に伴い、比較専用に追加していたstate・並行実行ロジックがあれば整理する(単一モデルでの通常実行フローに戻す)
3. `styles.css`に追加していた比較パネル専用のスタイルも、他で使われていなければ削除する
4. モデル選択(Sonnet/Opus/Local)自体は残し、引き続きどれか1つを選んで単独実行できるようにする(この部分は変更しない)

### Task 2: 実行時間の記録

1. 各実行(`runInsightAgent`/`runOllamaAgent`どちらも)について、開始時刻・終了時刻・所要時間(ミリ秒)を記録する。既に内部的に計測している箇所があれば流用してよい
2. `query-history.jsonl`の各レコードに`durationMs`(または同等のフィールド)を追加し、永続化する
3. 後方互換: 既存の履歴レコード(`durationMs`が無いもの)を読み込んでもエラーにならず、所要時間が「不明」等の表示になるようにする

### Task 3: タイムライン・履歴詳細への表示

1. 実行タイムライン(Timeline.tsx等、一覧表示部分)の各行に、使用モデル名の近くに所要時間(例: 「Sonnet・12.4秒」「Local(gemma4:12b)・47.2秒」)を表示する
2. セッションスレッド内の各ターン表示(Turn.tsx)にも同様に所要時間を表示する
3. 既存の履歴(durationMsが無いもの)は所要時間欄を空欄または「—」で表示する

### Task 4: 動作確認

1. 比較モードのチェックボックス・UIが完全に無くなっていることを確認する
2. Sonnetでクエリを実行し、実行タイムラインに所要時間が表示されることを確認する
3. Local(gemma4:12b)でクエリを実行し、同様に所要時間が表示され、Sonnetの実行より明らかに時間がかかっていることが数字で確認できることを確認する
4. 既存の古い履歴(比較モード実装前・durationMs無し)が壊れずに表示されることを確認する
5. ダークモード両テーマでの表示を確認する
6. `docker compose up -d --build`で反映し、実画面を確認する

## 完了報告

verified-report形式で報告すること。特に:

- 比較モードの削除範囲(削除したファイル・コード箇所)
- 所要時間記録・表示の実際の見た目(Sonnet実行とLocal実行それぞれの所要時間の実測値)
- 既存履歴(durationMs無し)の後方互換確認結果
- `docker compose up -d --build`後の反映確認結果

git操作は行わないこと。

---
**推奨モデル: Sonnet**(既存機能の削除と、計測値を記録・表示に足すだけの機械的な実装のため)
