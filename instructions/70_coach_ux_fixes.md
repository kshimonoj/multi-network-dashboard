# 70: Coachの不具合4件(応答速度・モデル、履歴閲覧、エスカレーションループ、ヒント追加の不自然な応答)

## 背景

- Coachタブ(64〜69番で実装)について、実際に使ってみたユーザーから4件のフィードバックがあった

## タスク

### Task 1: 応答速度・使用モデルの調査と見直し

1. Coachが現在どのモデルを使っているか(壁打ち応答生成・クイズ出題・採点それぞれ)を確認する
2. 応答が遅いと感じられている原因を特定する(モデルそのものの生成速度、ライブMCP呼び出し(68番で追加)の待ち時間、その他の処理のうちどれが支配的か)
3. Haiku等の軽量モデルへの切り替えを検討する。ただし68番で「もっともらしい誤りを作文する」問題が実際に起きた経緯があるため、軽量モデルへの変更が回答品質(特にソクラテス式のヒントの技術的正確さ)を犠牲にしないか、実際に試して比較検討する
4. モデル変更以外の速度改善(ライブMCP呼び出しの必要性判定を早める、並列化できる処理があれば並列化する等)の余地も確認する
5. 検討結果を踏まえて、速度と品質のバランスが取れた構成に変更する(モデル変更を伴う場合は変更後の品質を複数の話題で確認する)

### Task 2: 壁打ち履歴の閲覧機能

1. 過去の壁打ち(data/coach/sessions.jsonl等、既存の保存データ)を一覧・詳細で閲覧できる画面をCoachタブに追加する
2. セッション単位で、いつ・どんな話題で・何往復のやり取りをしたか一覧表示し、クリックで詳細(実際のやり取り全文)を確認できるようにする
3. 既存のUIパターン(Webhookログや調査履歴の一覧・詳細表示等)を参考にしてよい

### Task 3: エスカレーション(「もう答えを教えて」)後にまた質問が返ってくる問題の修正

1. 「もう答えを教えて」を押した後の回答生成ロジックを確認する。65〜68番で実装したhintLevel=3(強制開示)の応答テンプレート・プロンプトが、開示の最後に「次に同じ状況が起きたら、最初にどこを見る?」のような追加の質問を必ず付けてしまっている可能性が高い
2. これは3ターン規則等、通常のヒント段階でのやり取りでは意図した挙動(retrieval practiceの問いを添える)だが、**エスカレーション経由の開示では、それが「答えを教えたのにまだ質問される」というループに見えてしまう**問題だと考えられる。エスカレーション時は末尾の追加質問を付けない、または明確に「(任意)理解を定着させたければ考えてみて」等、質問ではなく提案であることが分かる形に変更する
3. 修正後、エスカレーションで実際に「答えが開示されて会話が一区切りつく」体験になっているか確認する

### Task 4: 「ヒントをもう1つ」クリック時の不自然な応答の修正

1. 添付されていたやり取り例を再現する: ある話題で壁打ちを進め、「ヒントをもう1つ」ボタンをクリックした際の応答を確認する
2. 現状、Coachが「相手の発言は『ヒントの続きを求めています』だけで、追加情報がまだ報告されていない」という趣旨の前置きをしてから初めてヒントを出しており、これが不自然(ボタンクリックはただのヒント要求であり、情報不足を指摘されるようなものではない)という指摘を踏まえて修正する
3. 原因を調査する: 「ヒントをもう1つ」ボタンクリックが、通常のチャット発言と同じように扱われ、utterance分類(67番)やhintLevel判定のロジックに「情報が無い発言」として引っかかっている可能性が高い。ボタンクリックによるヒント要求は、通常の発言とは区別して処理する必要がないか確認する
4. 修正後、「ヒントをもう1つ」を押した際は、前置きの指摘なしに、素直に次のヒントが出ることを確認する(添付の例のような「Coverage/Capacity/Roamingのどれが赤いか教えて」のような具体的なヒント内容自体は良い内容なので、そこは維持しつつ前置きだけを取り除く)

## 制約

- Central/Mistの設定変更は一切行わない
- git操作は行わない(コミット等は別途指示があるまで実施しない)
- 64〜69番で実装済みの機能(hintLevel管理、根拠リンク、ライブMCP、自アプリUI言及ガード等)を壊さないこと
- 実装完了後、本番Dockerコンテナのrebuildまで行い、本番ポート(8092)での動作確認まで実施する(標準運用ルール通り)

## 完了報告

verified-report形式で報告すること。特に:

- Task1: 速度低下の主因、モデル変更の有無とその判断根拠、変更した場合の品質確認結果
- Task2: 履歴閲覧機能の実装内容と動作確認結果
- Task3: エスカレーションループの原因と修正内容、修正後の動作確認結果
- Task4: 「ヒントをもう1つ」の不自然な応答の原因と修正内容、修正後の動作確認結果
- 本番反映の結果
- 未確認・次回に持ち越した事項
