# 47: 承認済みナレッジを調査プロンプトへ注入する(Loopを閉じる)

## 目的

46番で蓄積を始めた承認済みナレッジを、次のネットワーク調査(手動・自動問わず)のInsight Agent実行時に参照させ、既知の知見を踏まえた回答ができるようにする。これにより「調査→知見抽出→蓄積→次の調査に反映→調査に戻る」というLoopを閉じる。

## 方針(確定事項)

- マッチングは高度な埋め込み検索等を使わず、46番の重複検出と同様の軽量な手法(対象デバイス/サイト・タグ・キーワードの一致度)でよい
- 関連するナレッジが見つかった場合、system promptに「関連する既知の情報」として簡潔に注入する(症状・根本原因・対処法の要点のみ。長文を丸ごと入れてコンテキストを圧迫しないこと)
- 注入されたナレッジは、実際にその調査で参照された場合(モデルの回答がそのナレッジに言及した場合、またはそもそも注入された場合を「参照」とみなすかは実装しやすい方でよい)、参照回数と最終参照日時を更新する
- Claude(Sonnet/Opus)・Local(Ollama)どちらの実行経路でも同様に機能させる
- Webhookログ・レポートの自動事前調査からの実行でも同様に注入する(これらも既存のrunInsightAgentの経路を通るはずなので、共通化できるはず)

## タスク

### Task 1: マッチングロジックの実装

1. 調査クエリ実行時(サイト選択・クエリ本文が分かった時点)に、承認済みナレッジの中から関連しそうなものを抽出するロジックを実装する(対象サイト/デバイスの一致、クエリ本文とナレッジのタグ・症状文言との簡易的なキーワード一致度で判定する)
2. マッチする候補が多すぎる場合に備え、上位N件(例: 3件程度)に絞る仕組みを入れる
3. 何もマッチしない場合は、従来通り注入なしで実行する(既存の動作に影響を与えない)

### Task 2: system promptへの注入

1. `insight-agent.ts`のsystem prompt構築処理に、マッチしたナレッジがあれば「関連する既知の情報」セクションとして追加する処理を実装する(日英両方のプロンプトに対応。既存のi18n・言語連動の仕組みに沿わせる)
2. 注入する内容は簡潔にする(タイトル・症状・根本原因・対処法の要点のみ。出典の調査結果本文まるごとは含めない)
3. Ollama経由(Local LLM)の実行でも同様の注入が行われるようにする(ollama-agent.tsも同様に対応する)

### Task 3: 参照回数・最終参照日時の記録

1. ナレッジが調査プロンプトに注入された際、該当エントリの参照回数(+1)・最終参照日時を更新する仕組みを実装する
2. ナレッジタブの承認済み一覧に、参照回数・最終参照日時を表示する(46番で作成済みの画面に追加する形)
3. 一度も参照されていない古いナレッジが分かるようにする(例: 「未参照」の表示、または参照日時でのソート)。これは今回は表示のみでよく、自動削除等の仕組みは不要

### Task 4: Webhook/レポートの自動事前調査への適用

1. Webhookログの自動事前調査(enrich.ts)、レポートの自動事前調査(44番)も、同じrunInsightAgent経由であれば自動的にナレッジ注入の恩恵を受けるはずなので、実際にそうなっているか確認する。もし別経路になっていて注入が効かない場合は、その旨を完了報告で明記し、対応要否を判断する

### Task 5: 動作確認

1. 既に承認済みのナレッジがある状態で、そのナレッジに関連するサイト/デバイスについて調査を実行し、回答に既知の情報が反映されている(または少なくともプロンプトに注入されていることがログ等で確認できる)ことを確認する
2. 該当ナレッジの参照回数が増えることを確認する
3. 関連するナレッジが無いクエリを実行した場合、注入なしで従来通り動作することを確認する
4. Local(Ollama)経由の実行でも同様に注入されることを確認する
5. Webhook/レポートの自動事前調査でも注入が効いているか確認する(Task 4の結果を踏まえて)
6. 既存の調査結果・ナレッジタブの他機能に影響が無いことを確認する
7. `docker compose up -d --build`で反映し、実画面を確認する

## 完了報告

verified-report形式で報告すること。特に:

- マッチングロジックの実装内容と、実際にマッチした実データ例
- system promptへの注入内容の実例(実際にどう組み込まれたか)
- 参照回数・最終参照日時の更新確認結果
- Claude/Local両経路での動作確認結果
- Webhook/レポート自動事前調査への適用状況(効いているか、別経路だったか)
- `docker compose up -d --build`後の反映確認結果

git操作は行わないこと。
