# 29: i18n基盤構築 + UI言語とAgent回答言語の連動 + CLAUDE.md運用ルール記載

## 前提・確定事項(28番の結果を踏まえて)

- i18n基盤は追加ライブラリを導入せず、既存のダークモード切替と同じパターン(軽量な自前Context + JSON辞書ja.json/en.json)で実装する
- **UIの表示言語とInsight Agentの回答言語を連動させる**(UIを英語にすればAgentの回答も自動的に英語になる)
- `detectPlatformJudgment()`(insight-agent.ts:151-162)が正規表現で日本語の自然文(「不要と判断」「セントラル/ミスト」等)をパースしている問題は、**言語設定に関わらず**、言語非依存の機械可読マーカー方式に置き換える(これは英語化の有無を問わず直すべき構造的な弱点のため)
- 今回のスコープは基盤構築+共有/シェル部分(17件)の適用まで。各タブ本体の辞書化は30番以降で行う

## タスク

### Task 1: i18n基盤の構築

1. `src/i18n/`(仮)に、`ja.json`・`en.json`の辞書ファイルと、言語切替用のContext(`LanguageContext`)・`useTranslation()`または`t()`ヘルパーを新設する。既存のダークモード切替の実装パターン(Context/永続化の方法)を参考にする
2. 言語設定は永続化する(localStorage、または既存の設定永続化パターンを踏襲。Global Overviewのポーリング間隔設定等と同様の方式でよい)
3. 初期値は日本語(`ja`)とする

### Task 2: 言語切替UIの設置

1. ヘッダー(ダークモード切替と同じ並び)に、言語切替UI(トグルまたはプルダウン、"日本語"/"English")を設置する
2. 切り替えると、辞書経由で表示している文言が即座に反映されるようにする(この時点では共有/シェル部分の17件のみが対象)

### Task 3: 共有/シェル部分(17件)の辞書化

1. 28番のfindings(`instructions/28_findings.md`)に記載された「共有/シェル」区分の17件の静的ラベルを、辞書経由の表示に置き換える
2. タブ名(ネットワーク調査/Global Overview/Event Alert/Webhookログ/Streaming(Central))も辞書化する

### Task 4: UI言語とAgent回答言語の連動

1. `insight-agent.ts`のsystem prompt(28番で確認された「日本語で簡潔に答える」という強制指定の箇所)を、**現在のUI言語設定に応じて日本語/英語の指示を切り替える**ように修正する
2. フロントエンドから、現在のUI言語をInsight Agent実行APIのリクエストに含めて渡すようにする(クエリ本文とは別に、言語設定として渡す)
3. 既存の日本語UIでの動作(デフォルト言語が日本語の場合)に変化がないことを確認する

### Task 5: `detectPlatformJudgment()`のマーカー化(重要・言語非依存の対応)

1. system promptに、モデルが「このプラットフォームは不要と判断した場合、`[SKIP:central]`または`[SKIP:mist]`のような機械可読なマーカーを出力に含める」ことを指示する一文を追加する(日本語UI・英語UI両方のプロンプトに、同じマーカー形式を指示する。マーカー自体は言語に依存しない固定の記号にする)
2. `detectPlatformJudgment()`の実装を、既存の日本語自然文の正規表現パースから、上記マーカーの検出に置き換える
3. 後方互換は不要(過去の履歴データの表示が変わることは許容する)。ただし新しい実装が、日本語UI・英語UIどちらの回答からもマーカーを正しく検出できることを確認する
4. マーカー自体はユーザーに見える回答本文からは取り除いて表示する(内部的な判定にのみ使い、画面上にマーカー文字列がそのまま出ないようにする)

### Task 6: CLAUDE.mdへの運用ルール記載

1. プロジェクトの`CLAUDE.md`(無ければ新規作成)に、以下の趣旨のルールを追記する:
   - 「UIに新しい文言を追加する際は、必ず`src/i18n/ja.json`と`src/i18n/en.json`の両方に対応するキーを追加すること」
   - 「動的に組み立てる文字列(クエリ生成・共有テキスト・印刷レイアウト等)を新設する場合も、日英両方のテンプレートを用意すること」
   - 「モデル出力を自然言語でパースする実装(`detectPlatformJudgment()`のような)は作らず、マーカー等の機械可読な方式にすること」

### Task 7: 動作確認

1. 言語切替UIで日本語⇔英語を切り替え、共有/シェル部分(タブ名含む)の表示が切り替わることを確認する
2. 英語表示に切り替えた状態でネットワーク調査を実行し、Insight Agentの回答が実際に英語で返ることを確認する
3. 日本語表示のままでも、`detectPlatformJudgment()`のマーカー方式が正しく機能する(「モデル判断による省略」表示が壊れていない)ことを確認する
4. 英語表示でも同様にマーカー方式が機能することを確認する
5. 各タブ本体(まだ辞書化していない部分)は日本語のまま表示され続けることを確認する(30番以降で対応するため、今回はこれで問題ない)
6. ダークモード両テーマでの表示を確認する
7. `docker compose up -d --build`で反映し、実画面を確認する
